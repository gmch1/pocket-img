# Spec 003：GitHub 一键安装后端

状态：已实现，待提交和发布

## 目标与基线

基线 `e6789e9` 已有本地二进制安装脚本和自动 Token 初始化，但仍要求用户取得二进制与仓库。新增 GitHub 入口，用户执行一条命令即可下载、校验、安装并得到 Token。

本规格扩展 Spec 001，自动下载不再排除在范围外。复用其 systemd 安装、凭证复用和数据保护行为。

## 行为

- 入口为根目录 `install.sh`，支持 Linux x86_64 / systemd；依赖 Bash、curl、Python 3、tar、sha256sum 和常规系统管理工具，不依赖 Git、Go、Node.js 或 Docker。
- 自动枚举 GitHub Releases，按数字版本选择带安装包及 SHA-256 的稳定 `server-v*` 发布；排除草稿、预发布、其他组件与不兼容旧包，不使用 GitHub Latest。
- 支持指定版本、`--port` 和仅下载模式。下载失败、SHA-256 不符、压缩包文件结构异常时不运行安装脚本。
- 每份安装包含同版本的后端二进制、安装脚本与 systemd unit；禁止混用 main 脚本和历史二进制。
- 校验完成后调用包内安装脚本，继续复用已有凭证；成功后显示管理员 Token。
- 后端只提供 HTTP，新安装器默认 `127.0.0.1:18746`。`--port` 支持 `1024–65535`，只改端口，不改变监听主机或 Cookie 模式；Linux 端口被其他服务占用时停止，不改写配置。
- 已有 Linux 安装复用配置中的端口，显式 `--port` 才修改并持久化；原 Token 保持有效。
- Docker 默认宿主机端口改为 `18746`，支持 `--port`、`PIH_PORT` 与 `.env`；未指定时安装器复用已有容器映射。直接使用 Compose 或删除容器后重建须用 `.env` 保存自定义端口。
- 为兼容历史部署，裸二进制默认仍为 `8080`，Docker 内部、Android 和飞牛映射不改动。用户管理 Nginx/Caddy 等外部 HTTPS 入口；脚本不申请证书、不修改代理或防火墙。

## 发布边界

推送 main 自动触发 CI，不发布二进制。正式交付还需要发布包含安装包的 Server Release；历史 `server-v0.5.2` 不符合要求。脚本与附件尚未上线时，文档明确标记尚不能作为可用公网入口。

正式发布通过组件工作流单独执行，不由安装脚本触发。Docker 镜像的发布继续沿用 fnOS 流程，与 Server 二进制发布分开。

## 验收

自动选择正确组件和版本；显式版本有效；错误校验和、异常归档与无兼容版本都失败关闭；仅下载不覆盖已有目录；实际二进制打包后能解压初始化。正式发布后再验证公网一条命令安装。
