# Phone Image Host v1 需求基线

状态：核心需求已确认
日期：2026-08-11

## 1. 产品目标

提供一个主要面向 PC 浏览器的轻量图床：用户在页面内直接粘贴图片，系统完成鉴权、上传、格式转换和存储，并返回可公开访问的图片 URL。

系统是单实例、多空间工具。每个 Token 对应一个彼此隔离的图库用户；一个由部署配置指定的主空间具有管理员能力，可以创建新用户 Token。系统不提供公开注册、密码账号、用户资料或任意角色/权限组。部署环境之外的域名、TLS、DDNS 和反向代理由外部运维设施负责，本服务只接收 HTTP 请求。

## 2. 范围边界

### 2.1 v1 包含

- PC Web 页面。
- 从系统剪贴板粘贴一张或多张图片。
- 使用预配置 Token 换取对应图库空间的管理会话。
- 上传进度、成功和失败状态。
- 单图上传成功后自动复制公开 URL。
- 按今天、最近 7 天、最近 30 天和全部筛选图片。
- 图片按上传时间倒序，以瀑布流展示。
- 长按进入多选模式，支持批量永久删除。
- 系统将静态图片转换为全尺寸 WebP，并由服务端为所有图片生成瀑布流缩略图。
- 图片公开访问，无需 Token。
- 管理员创建独立用户 Token，并查看各用户的图片数量与配额占用。
- 每个用户默认使用不超过 10 GiB，图片默认保留 90 天后永久清理。

### 2.2 v1 不包含

- 公开注册、密码登录、用户资料、任意角色/权限组以及空间之间的共享或协作。
- 网络请求转发、代理下载、URL 转存或远程抓图。
- DDNS、域名、TLS 证书或反向代理管理。
- 对象存储、S3、云存储和第三方服务依赖。
- 图片编辑、相册、标签、评论、分享密码和过期链接。
- 面向手机触屏操作的原生图库客户端；可提供只负责启停和配置后端的 Android 部署管理壳。

## 3. 鉴权模型

### 3.1 服务端

- 服务启动前配置一个或多个图库空间。每个空间由稳定的空间 ID 和当前长期 Token 组成，优先通过权限受限的 JSON 文件提供。
- 每个长期 Token 只用于换取其所属空间的浏览器会话，不直接用于每次列表、上传和删除请求。
- Token 是可轮换的凭据，不是数据主键。图片归属于稳定空间 ID；修改 Token 不改变历史数据归属。
- 同一个 Token 不能同时配置给多个空间，空间 ID 不能直接使用 Token 或 Token 哈希。
- Token 交换请求使用 `Authorization: Bearer <token>`，服务端只用 Token 的 SHA-256 指纹查询启用用户。
- Token 不允许放在 URL 查询参数中，避免进入访问日志和浏览器历史。
- Token 应为密码学安全的高熵随机值，不使用便于记忆的短密码。

### 3.2 会话交换

1. 页面在没有有效会话时显示 Token 输入框。
2. 页面调用 `POST /api/auth/session`，仅这次请求携带长期 Token。
3. 校验成功后，服务端生成至少 256 bit 的随机会话凭据。
4. 浏览器只收到 Session Cookie；服务端只保存会话凭据的哈希、所属空间 ID、签发时间、过期时间和当前 Token 指纹。
5. 后续图片列表、上传和删除请求由浏览器自动携带 Cookie，不再传输长期 Token。
6. 默认会话有效期为 7 天，并允许通过服务配置调整。
7. 主动退出会删除并吊销当前会话；某个空间的 Token 发生变化时，仅该空间的既有会话全部失效，其他空间不受影响。

Session Cookie 使用以下属性：

- `HttpOnly`：前端 JavaScript 无法读取。
- `Secure`：只允许浏览器通过 HTTPS 发送。
- `SameSite=Strict`：降低跨站请求伪造风险。
- `Path=/api`：访问公开图片时不携带管理会话。
- 不设置 `Domain`：Cookie 仅属于当前主机。

所有会修改数据的 Cookie 鉴权接口还需要校验 `Origin`，服务端默认不开放 CORS。

### 3.3 鉴权边界

| 能力 | 鉴权方式 |
| --- | --- |
| 打开前端静态页面 | 否 |
| 换取管理会话 | 长期 Token |
| 读取图片列表和元数据 | Session Cookie |
| 上传图片 | Session Cookie |
| 删除图片 | Session Cookie |
| 创建用户 Token、读取用户列表 | 管理员 Session Cookie |
| 访问已知图片直链 | 否 |
| 访问瀑布流缩略图直链 | 否 |

图片列表需要有效会话，但已知图片 URL 可以公开访问。这样不会公开暴露完整图库索引，同时图片能直接用于 Markdown、论坛和其他网页。

每个管理会话只属于一个空间。图库列表、上传、单图删除和批量删除都必须从服务端 Session 中取得空间 ID，不能接受客户端提交 `owner_id`；任何跨空间图片 ID 的删除请求都按“不属于当前空间”处理。

### 3.4 页面中的 Token

- 页面提供固定、易发现的 Token 设置入口。
- 页面只在交换会话所需的内存中短暂持有 Token，不写入 Local Storage、Session Storage、IndexedDB 或普通 Cookie。
- 交换完成后立即清空 Token 输入值，页面无法读取 `HttpOnly` Session Cookie。
- 页面提供“更换 Token”和“退出会话”入口。
- API 返回 `401` 时，页面清理当前状态并引导用户重新输入 Token。

### 3.5 传输安全边界

Token 换 Cookie 的作用是减少长期 Token 的传输次数，并避免长期 Token 被前端脚本持续读取；它不提供传输加密。Session Cookie 本身也是临时凭据，被抓取后在过期或吊销前仍可能被冒用。

- 浏览器到外部入口必须使用 HTTPS，这是防止公网或客户端链路抓包的必要条件。
- 外部入口终止 TLS 后到本服务的 HTTP 链路是明文链路。
- 如果还需要保护外部入口到手机之间的流量，应由反向代理 HTTPS、WireGuard 等加密链路解决。
- 本服务不实现隧道、证书、DDNS 或其他网络层能力。

## 4. 粘贴与上传流程

1. 页面监听 `paste` 事件。
2. 遍历剪贴板中的所有项目，只接收 MIME 类型为 `image/*` 的项目。
3. 剪贴板不含图片时不发起请求，并给出简短提示。
4. 检测到图片后立即加入上传队列，不要求再次确认。
5. 对大于等于 256 KiB 的 PNG/JPEG，浏览器优先在 Worker 中以质量 82 编码为同尺寸 WebP；只有输出类型确为 WebP 且至少缩小 10% 时才使用优化结果。
6. 浏览器不支持 Worker、Canvas 或 WebP 编码、编码失败、压缩收益不足时，自动上传原文件，不把优化失败当作上传失败。
7. GIF 和已有 WebP 不做浏览器重编码，避免丢失动画或重复压缩。
8. 每张图片独立展示优化、上传进度和结果；部分失败不影响其他图片。
9. 只有一张图片且上传成功时，页面尝试自动把公开 URL 写入系统剪贴板。
10. 自动写入失败时，页面必须保留 URL，并显示明确的“复制”按钮作为降级方案。
11. 同时上传多张图片时不自动覆盖剪贴板，结果区提供“复制全部 URL”。

自动复制依赖浏览器 Clipboard API。生产入口需要提供 HTTPS，否则浏览器可能拒绝剪贴板写入；这不要求本服务自身处理 TLS。

## 5. 图片处理与存储

### 5.1 处理结果

静态图片成功上传后生成两个文件：

- 全尺寸优化图：保持原始宽高，不主动缩小，编码为 WebP，作为公开图片直链；可由浏览器预编码，也可由服务端兜底编码。
- 瀑布流缩略图：限制长边尺寸，编码为较低质量 WebP，只用于列表展示。

GIF 和其他受支持的动图不转换全尺寸内容：原样保存动图文件，并额外生成一张静态 WebP 缩略图用于瀑布流。

前端瀑布流不得直接加载全尺寸图片。

### 5.2 已确认的默认参数

参数在实现时做成服务端配置，初始建议值如下：

| 参数 | 默认值 |
| --- | --- |
| 全尺寸 WebP 质量 | 82 |
| 缩略图 WebP 质量 | 75 |
| 缩略图长边 | 640 px |
| 单文件上传上限 | 25 MiB |
| 单次粘贴数量上限 | 20 张 |
| 解码像素上限 | 20 MP |
| 每用户实际存储配额 | 10 GiB |
| 图片默认保留时间 | 90 天 |

### 5.3 文件与元数据

- 图片内容存为普通文件，不写入 SQLite BLOB。
- SQLite 只保存空间 ID、图片 ID、文件路径、MIME、宽高、字节数、哈希和上传时间等元数据。
- 文件路径使用不可预测的随机 ID 或内容哈希分层，避免单目录文件过多。
- 文件在 `objects/{space_id}/...` 和 `thumbnails/{space_id}/...` 下按空间分区；公开 URL 不包含空间 ID。
- 上传先写临时文件，格式校验和转换成功后再原子移动到正式目录。
- 数据库存储 UTC 时间；“今天”等筛选按服务配置的 `Asia/Shanghai` 时区计算。
- 配额按全尺寸文件和已生成缩略图的实际字节数计算；正式元数据写入与配额判断在同一事务中完成。
- 后台按用户保留天数清理过期图片；删除文件、缩略图和元数据的语义与手动永久删除一致。
- 静态图片转换成功后删除上传临时原文件，不保留原图副本。
- 动图的正式文件就是上传原文件，不额外保留第二份原图。

### 5.4 初步格式策略

- v1 支持 PNG、JPEG、静态 WebP、GIF 和动态 WebP。
- 不能只相信请求中的 MIME；后端必须解码验证确实是图片。
- SVG 不作为图片上传接受，避免公开访问时引入脚本内容。
- PNG、JPEG 和静态 WebP 统一输出为 WebP，不保留 PNG/JPEG 输入原文件。
- 后端对所有上传继续执行真实格式、解码、像素数和动画校验，不能信任浏览器提交的 MIME 或文件名。
- 结构完整、无动画、无元数据和未知 RIFF 块的静态 WebP 可在完整校验后直接保存，避免再次有损编码。
- 带 ICC、EXIF、XMP 或未知 RIFF 块的静态 WebP 继续由后端重编码，以维持元数据净化行为。
- GIF、动态 WebP 等动图原样存储，不重新编码、不降低质量、不移除动画帧。
- 动图只额外提取首帧，生成静态 WebP 缩略图供瀑布流展示。
- HEIC/HEIF 暂不列入 v1 支持范围。
- 后端必须限制解码后的总像素数，避免尺寸很小但解码内存极大的图片耗尽内存；根据首轮真机压测，v1 默认上限为 20 MP，并继续保持单 worker。

## 6. 图片浏览

### 6.1 时间筛选

页面提供以下选项：

- 今天：从本地时区当天 00:00 至当前时间。
- 最近 7 天：包含今天在内的最近 7 个自然日。
- 最近 30 天：包含今天在内的最近 30 个自然日。
- 全部：不限制时间。

### 6.2 排序和分页

- 默认按 `created_at DESC, id DESC` 稳定倒序排列。
- 使用游标分页和滚动加载，不使用随数据变化容易重复或遗漏的 offset 分页。
- 初次加载和切换筛选时只请求首屏所需数据。

### 6.3 瀑布流

- 卡片根据图片宽高预留比例，减少加载后的布局跳动。
- 列表只请求缩略图。
- 单击图片显示大图预览及公开 URL。
- 每张卡片下方固定显示“复制”和“删除”图标按钮，不显示按钮文字。
- 复制图标按钮把该图片的全尺寸公开 URL 写入系统剪贴板，并显示短暂的成功或失败反馈。
- 删除图标按钮使用明确的危险色状态，发起单图永久删除，删除前必须二次确认。
- 两个图标按钮不显示悬停提示、文字标签或其他辅助说明，保持卡片操作区简洁。
- 点击卡片操作按钮不得同时触发大图预览或长按选择。
- 图片加载失败时显示占位状态，不破坏整体布局。

## 7. 多选与删除

- 鼠标或触控长按图片进入多选模式，建议触发时间约 500 ms。
- 进入多选后，单击卡片用于切换选择状态。
- 进入多选模式后，卡片下方的“复制”和“删除”操作栏切换为选择状态，避免与批量操作冲突。
- 页面显示已选择数量、全选当前已加载项、删除和退出多选操作。
- 删除前必须二次确认，并明确显示删除数量。
- 单图删除和批量删除复用同一接口；单图删除的请求体只包含一个图片 ID。
- 删除为永久删除：同时删除全尺寸图、缩略图和数据库记录。
- 批量删除接口必须要求有效的 Session Cookie。
- 个别文件删除失败时，接口返回逐项结果，页面不得把失败项误标为已删除。

## 8. HTTP 接口草案

具体字段可在技术设计阶段调整，但能力边界如下：

| 方法与路径 | 鉴权 | 用途 |
| --- | --- | --- |
| `GET /` | 否 | 内嵌前端页面 |
| `POST /api/auth/session` | 长期 Token | 换取 Session Cookie |
| `DELETE /api/auth/session` | Session Cookie | 退出并吊销会话 |
| `GET /api/images` | Session Cookie | 时间筛选和游标分页 |
| `POST /api/images` | Session Cookie | 上传一张或多张图片 |
| `DELETE /api/images` | Session Cookie | 批量永久删除 |
| `GET /api/admin/users` | 管理员 Session Cookie | 用户、配额与使用量列表 |
| `POST /api/admin/users` | 管理员 Session Cookie | 创建用户并一次性返回新 Token |
| `GET /i/{id}.{ext}` | 否 | 全尺寸 WebP 或原样动图 |
| `GET /t/{id}.webp` | 否 | 公开缩略图 |
| `GET /healthz` | 否 | 本机或反向代理健康检查 |

上传响应必须返回稳定的相对公开路径。页面以当前外部访问来源拼成完整 URL，因此服务端不需要知道 DDNS 域名；若未来图片域名和页面域名分离，再增加可选的 `public_base_url`。

## 9. 部署与运行约束

- 服务只监听普通 HTTP，不申请或更新证书。
- 不执行任何出站网络请求。
- 不实现 DDNS、端口映射和反向代理。
- 后端和前端开发阶段只提供可信局域网 HTTP 服务，不包含外部入口；内网开发实例允许显式关闭 Session Cookie 的 `Secure` 属性。
- 外部域名、HTTPS、DDNS 和请求转发由独立运维设施负责，接入时必须恢复 Session Cookie 的 `Secure` 属性。
- v1 不实现请求频率限制；仍保留上传体积、解码像素、队列长度和单 worker 限制。
- 前端使用 React + TypeScript 构建纯 SPA，不使用 SSR；Node 只作为开发和构建工具，不进入设备运行环境。
- 后端使用 Go，以单个 ARM64 进程运行并内嵌前端资源，避免 Node、PostgreSQL、Redis 和 Docker 等运行时依赖。
- 数据目录、监听地址、端口、管理员空间、引导 Token 映射、会话有效期、时区和图片参数由启动配置提供。
- 服务重启后上传记录和公开 URL 保持稳定。

## 10. v1 验收标准

- 在 PC 页面粘贴一张有效图片后，无额外点击即可开始上传。
- 正确 Token 能换取带有 `HttpOnly`、`SameSite=Strict` 属性的 Session Cookie；生产 HTTPS 模式还必须带 `Secure`，内网 HTTP 开发模式显式关闭 `Secure`。
- 长期 Token 不写入任何浏览器持久化存储，后续管理请求不再携带长期 Token。
- 没有有效 Session Cookie 的列表、上传和删除请求返回 `401`，且上传失败时不会留下正式文件。
- 单图上传完成后，公开 URL 被自动复制；浏览器拒绝时提供一次点击复制方案。
- 无需鉴权即可正常访问公开图片 URL。
- 未建立有效会话时不能获取图片列表、上传或删除。
- 不同 Token 换取的会话只能看到、上传和删除各自空间的图片；一个空间不能通过提交另一个空间的图片 ID 删除其文件。
- 单个空间轮换 Token 后，该空间旧 Token 和旧 Session 立即失效，新 Token 登录后仍能看到原有图片；其他空间的 Session 保持有效。
- 列表能正确切换今天、最近 7 天、最近 30 天和全部。
- 瀑布流按时间稳定倒序，并且网络请求加载的是缩略图。
- 每张瀑布流卡片都能直接复制公开 URL，并能在二次确认后永久删除该图片。
- 长按可进入多选，确认后可批量删除，刷新页面后已删除图片不再出现。
- 重启服务后历史图片、元数据和 URL 不发生变化。
- 服务在运行期间不会发起外部网络请求。
- 静态图片上传成功后只保留全尺寸 WebP 和缩略 WebP。
- 支持 WebP 编码的浏览器上传较大 PNG/JPEG 时优先在 Worker 中预压缩；能力缺失或收益不足时能无感降级。
- 后端收到浏览器预压缩的安全静态 WebP 时不重复编码全尺寸图，但仍校验内容并重新生成缩略图。
- GIF 和动态 WebP 的公开文件内容保持原样，瀑布流使用额外生成的静态 WebP 缩略图。
- 批量删除后图片文件、缩略图和元数据均被永久删除，不存在回收站副本。

## 11. 已确认的产品决定

1. 图片列表需要有效会话；单张图片和缩略图公开访问。
2. 静态图片不保留原图，统一保存为全尺寸 WebP 和缩略 WebP。
3. GIF、动态 WebP 等动图原样保存，只额外生成静态 WebP 缩略图。
4. 删除为永久删除，不提供回收站。
5. 默认采用 25 MiB 单图、20 张单次粘贴和 640 px 缩略图限制。
6. 长期 Token 只用于换取短期 Session Cookie，不在浏览器中持久化。
7. 每个预配置 Token 对应一个独立图库空间；空间 ID 是稳定数据归属，Token 可以轮换。
8. 采用共享 SQLite 表加 `owner_id` 的逻辑分区，不为每个 Token 动态创建表或数据库。
