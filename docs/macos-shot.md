# macOS 截图上传客户端

`PocketIMG Shot` 是 PocketIMG 的原生 macOS 菜单栏客户端。它提供一条精简工作流：

```text
F1 → 拖拽选择区域 → 方框/箭头/文字标注 → 贴图置顶、复制图片或上传并复制公开 URL
```

客户端要求 Apple Silicon（`arm64`）和 macOS 14 或更高版本，使用 ScreenCaptureKit 截图，通过现有 `POST /api/auth/session` 和 `POST /api/images` 接口上传，不需要单独部署桌面端 API。正式版本不再提供 Intel 或 Universal 归档。

## 当前能力

- 菜单栏常驻，不显示 Dock 图标。
- 应用程序包使用独立的 PocketIMG Shot 图标，便于在 Finder、应用程序目录和系统设置中识别；菜单栏使用与应用图标呼应的“四角截图框 + 上传箭头”单色模板图标，并自动适配浅色和深色外观。
- 新安装的默认全局快捷键为 `F1`，可以在设置中录制其他功能键或带修饰键的组合；录制完成后立即保存。
- 支持多显示器区域选择，并按屏幕 backing scale 捕获 Retina 原生像素；按快捷键后直接进入全屏捕获流程，不进入系统内容共享选择器。
- 按下截图快捷键后会立即用透明输入层接管鼠标和键盘；即使马上按住鼠标拖动，也会等当前手势释放后再进入选区，期间不会显示额外的准备提示，并可随时按 `Escape` 取消。
- 在副显示器完成截图后，贴图会使用该显示器的局部坐标创建窗口，并校正回全局位置，避免因屏幕原点偏移而落到屏幕外。
- 冻结画面只在选区外叠加半透明灰黑遮罩，不使用高斯模糊；选区直接显示原始清晰截图。
- 选区阶段在指针附近显示像素放大预览、十字准星、像素坐标和十六进制颜色值。
- 完成选区后默认不激活标注工具；直接拖动选区内部可以在屏幕范围内整体移动选区，已有标注同步移动；拖动四条边或四角控制点可以继续调整截图范围。
- 支持方框、箭头和文本；选择 `A` 后点击截图位置输入文字，点击点作为文字行的垂直中心，按回车确认。
- 方框、箭头和文本需要手动点击后才会激活；再次点击当前工具可取消选择并回到选区移动状态。
- 方框、箭头或文字绘制完成后保持当前选中；在点击其他位置使其失焦前，方框边线与内部、箭头线段、文字输入框或文字主体都会显示张开的小手，拖动时切换为握紧的小手并直接调整位置。
- 标注失焦后，空心方框只在边线上命中，内部恢复为当前画布操作；方框四角和文字右下角使用对应的斜向缩放光标，箭头首尾使用十字光标调整端点。
- 点击截图空白处才开始绘制下一个标注；取消当前工具后可悬停并编辑任意已有标注。
- 工具栏颜色按钮提供红、黄、绿、蓝、紫、白 6 个 Snipaste 风格常用色（`#FF0000`、`#FFF200`、`#22B14C`、`#00A2E8`、`#A349A4`、`#FFFFFF`），选择后应用到后续方框、箭头和文字，并在下次截图时继续沿用。
- 文字输入态使用 18% 黑色轻遮罩和系统强调色焦点效果；placeholder、输入文字和最终标注统一使用当前颜色。滚轮调整字号时 placeholder 会同步缩放，并继续按当前字体行高垂直居中。
- 方框和箭头共享一组线宽，默认使用 2 点细线；调整其中任意一个时另一个同步更新。文字字号保持独立；浮层会短暂显示当前数值，后续截图与应用重启后继续沿用。
- 绘制过程中滚动滚轮会立即修改正在绘制的方框、箭头线宽或文字字号；绘制完成且标注仍为当前选中对象时，滚轮继续修改该标注本身，而不只是修改下一个标注的默认值。
- 支持工具栏撤销、`Command-Z`、`Command-C` 复制并退出和 `Escape` 取消；后端配置完整时，`Return` 可以直接上传。
- 工具栏右侧始终提供贴图和复制；只有服务地址与 Token 均有效时才显示最右侧的上传按钮，未配置后端时 `Return` 不执行任何上传动作。
- 贴图不会上传或修改剪贴板，会在原截图选区的位置和尺寸创建带轻微强调色边缘的置顶图片；可同时保留多张，支持拖动和鼠标滚轮按比例缩放，双击、`Escape` 或右键菜单关闭。
- 复制会把合成标注后的截图图片写入系统剪贴板，不会上传。
- 上传成功后把公开 URL 写入系统剪贴板。
- 启动后每天通过 macOS 专用的滚动 appcast 检查一次 GitHub Release；菜单栏也提供“检查更新…”。发现新版后由应用下载、验证、替换并重启，不需要手动解压覆盖。
- 自动更新使用比 ZIP 更小的 tar.xz 归档，手动下载仍保留 ZIP；更新归档和 appcast 均使用独立 Ed25519 密钥签名，应用在解压前验证签名，发布工作流缺少更新私钥时会直接失败。
- 服务地址、Token 和快捷键保存在 `~/Library/Application Support/PocketIMGShot/settings.json`，目录权限为 `0700`、文件权限为 `0600`，不访问钥匙串；Session Cookie 只保存在当前进程。
- 设置页可选择跟随系统、简体中文或 English；语言选择写入同一配置文件，菜单栏、快捷键录制、截图文字输入、贴图菜单、状态提示和错误窗口会立即使用所选语言。
- 未标版本的旧配置若仍是早期默认 F2，会一次性迁移为 F1；此后用户主动设置的 F2 不会再次迁移。
- 截图自动限制在 19 MP 以内；上传动作在 Mac 端编码为质量 82 的 WebP，减少公网传输并让后端直接落盘。复制和贴图仍使用 PNG；WebP 编码不可用时自动回退 PNG，超过 24 MiB 再尝试 JPEG。

暂未实现马赛克、画笔、窗口吸附、长截图和本地历史记录。

## 开发与运行

在安装了 Xcode 16 或更高版本的 Mac 上打开：

```bash
open macos/PocketIMGShot.xcodeproj
```

选择 `PocketIMGShot` scheme 后运行。Xcode 会通过 Swift Package Manager 获取固定版本的 Sparkle 更新框架。工程的本地开发构建默认使用 ad-hoc 签名，开发阶段无需配置发布证书。GitHub Release 使用固定的 PocketIMG 自签名证书，首次启动仍需要在 Finder 中右键应用并选择“打开”。需要免提示分发或 Apple 公证时，仍需换成 Apple Developer Program 提供的 Developer ID Application 证书。

也可以从仓库根目录运行：

```bash
make macos-test
make macos-build
```

首次截图时，macOS 会要求“屏幕与系统音频录制”权限。这个名称是 macOS 对屏幕捕获权限类别的系统文案；客户端只在按下快捷键时获取一张静态画面，捕获配置明确关闭音频，也不会创建持续共享流。功能键行为受系统键盘设置影响；部分 Mac 键盘需要按 `Fn-F1` 才会发送标准 F1。

从 `0.4.5` 开始，GitHub Release 固定使用同一份长期自签名证书，Bundle ID 保持为 `com.gmch.pocketimg.shot`。由 `0.4.4` 或更早的 ad-hoc 版本升级到 `0.4.5` 时，代码身份发生最后一次切换，macOS 仍可能要求重新授予一次屏幕录制权限；后续使用同一证书签名的版本应当复用这次授权。该证书不是 Apple Developer ID，因此不能消除首次启动时的 Gatekeeper 提示，也不能进行 Apple 公证。

自动更新从 `0.4.17` 开始提供。`0.4.16` 及更早版本没有更新器，因此需要最后一次从 GitHub Release 手动下载并覆盖安装；安装 `0.4.17` 或更高版本后，后续升级可以在应用内完成。更新不会修改 `~/Library/Application Support/PocketIMGShot/settings.json`，服务地址、Token、快捷键与标注样式会继续复用。

macOS 从组件化发布开始使用 `macos-v<version>` 标签。版本化 Release 保存应用归档，固定的 `macos-appcast` Release 只维护当前签名更新清单，因此 Server 或 Android 发布不会改变客户端看到的更新源。完整标签与发布规则见[组件发布流程](releases.md)。

macOS 新版本只支持 Apple Silicon。更新清单显式标记 `arm64` 硬件要求，已安装旧 Universal 版本的 Intel Mac 会继续停留在最后一个兼容版本，不会下载或安装无法运行的新版本。

截图生成和上传阶段会把不含 Token、服务 URL 和图片内容的诊断记录写入 `~/Library/Logs/PocketIMGShot.log`。发生错误时应用会显示错误窗口并给出该路径。

## 首次配置

贴图与复制可以直接使用；仅上传需要完成以下配置：

1. 点击菜单栏相机图标并打开“设置”。
2. 填写 PocketIMG 根地址，例如 `https://img.example.com` 或局域网开发地址 `http://192.168.1.20:8080`。
3. 填写当前空间的长期 Token。
4. 如有需要，点击快捷键框后按下新的组合。
5. 保存设置，然后按 `F1` 开始截图。

客户端首次上传时用 Token 换取 Session；后续复用 Session。服务返回 `401` 时会自动重新认证并重试一次。上传失败不会修改剪贴板，且会保留当前编码后的截图供用户重试。
